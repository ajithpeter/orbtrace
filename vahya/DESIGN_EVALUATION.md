# Vahya MINI Hardware Design Evaluation

**Date**: 2025-11-22
**Evaluator**: AI Analysis based on VAHYA_MINI_SCH.PDF (Rev. 4/01/2025)
**Hardware Version**: Vahya MINI
**PCB Revision**: 4/01/2025

## Executive Summary

The Vahya MINI hardware design represents a well-integrated SDR and GNSS platform with good design practices. The design successfully integrates multiple high-speed interfaces (USB 2.0 HS, LVDS data streams, multi-GNSS frontend) on a compact board with an ECP5 FPGA.

**Overall Rating**: ✅ **Good Design** (with minor recommendations)

**Strengths**:
- Clean power distribution with proper sequencing
- Good clock domain separation
- Appropriate use of differential signaling for high-speed data
- Comprehensive decoupling
- Multi-standard GNSS support
- Dual-band RF transceiver integration

**Areas for Improvement**:
- Some cross-bank differential pairs
- Missing termination on some high-speed signals
- Limited FPGA resource headroom with LFE5U-25F

## Detailed Evaluation

### 1. FPGA Selection

**Component**: Lattice ECP5 LFE5U-25F-7BG256I

**Strengths**:
- ✅ Industrial temperature range (-40°C to +100°C)
- ✅ Speed grade -7 appropriate for 75 MHz system clock
- ✅ Adequate resources for basic SDR/GNSS application:
  - 24K LUTs
  - 24K Flip-flops
  - 56 BRAM blocks (18Kbit each) = 1008 Kbit total
  - 28 DSP slices (though none used in current design)
- ✅ BG256 package provides good pin count for interfaces

**Concerns**:
- ⚠️ **Resource Utilization**: Estimated ~60% LUT utilization with full SoC
  - VexRiscv CPU: ~2K LUTs
  - USB LUNA stack: ~5K LUTs
  - AT86RF215 capture modules: ~2K LUTs
  - MAX2771 capture modules: ~1K LUTs
  - LiteX infrastructure: ~5K LUTs
  - **Recommendation**: Consider LFE5U-45F for production if adding more features

**Rating**: ✅ Good (adequate for current design, limited headroom)

### 2. Power Distribution

**Regulators**: TLV62569APDRLR (3× buck converters)

**Power Rails**:
1. **+3V3** (2A max): FPGA IO, ESP32, USB3343, peripherals
2. **+2V5** (1A max): FPGA VCCAUX, MAX2771 analog
3. **+1V1** (2A max): FPGA VCC core

**Strengths**:
- ✅ Proper power sequencing (3.3V first, then 2.5V and 1.1V simultaneously)
- ✅ Adequate current capacity for all rails
- ✅ Power-good indicators for monitoring
- ✅ Switching regulators for efficiency
- ✅ Proper inductor selection (2.2µH for all rails)
- ✅ Good decoupling strategy:
  - Bulk capacitors (22µF tantalum)
  - Ceramic decoupling (2.2µF, 0.1µF, 0.01µF)
  - FB beads for noise isolation between analog and digital

**Decoupling Capacitors**:
- ✅ Each VCCIO bank: 0.1µF + 0.01µF pair
- ✅ VCC core: Multiple 0.01µF distributed
- ✅ VCCAUX: 0.1µF + 0.01µF
- ✅ USB3343: Separate 1.8V and 3.3V decoupling
- ✅ MAX2771: Isolated analog supply with FB bead

**Concerns**:
- ⚠️ No bulk capacitance on +1V1 rail (only output caps)
  - **Recommendation**: Add 47µF-100µF bulk cap near U6 output
- ⚠️ No common-mode chokes on USB VBUS
  - **Recommendation**: Add CM choke for better EMI compliance

**Power Budget**:
| Rail | Typical | Max | Margin |
|------|---------|-----|--------|
| +3.3V | ~800mA | 2000mA | 2.5× |
| +2.5V | ~300mA | 1000mA | 3.3× |
| +1.1V | ~1200mA | 2000mA | 1.7× |

**Total Power**: ~8W typical, ~12W max (good thermal margin)

**Rating**: ✅ **Excellent**

### 3. Clock Architecture

**Primary Clocks**:
1. **26 MHz System** (Y2: ECS-TXO-32CSMV-260-AN-TR)
   - ✅ TCXO for stability
   - ✅ Feeds FPGA, AT86RF215, USB3343
   - ✅ Single source reduces jitter accumulation

2. **60 MHz USB ULPI** (from USB3343 CLKOUT)
   - ✅ Generated by USB3343 from 26 MHz reference
   - ✅ Directly to FPGA PCLK pin (K1)

3. **16.368 MHz GNSS** (Y4: 16.368MHz oscillator)
   - ✅ Optimal for GPS L1 sampling
   - ✅ Feeds MAX2771
   - ✅ CLKOUT to FPGA for ADC synchronization

4. **40 MHz ESP32** (Y5: 40 MHz crystal)
   - ✅ Standard ESP32-S3 clock
   - ✅ Isolated from FPGA clocks

**Strengths**:
- ✅ Clean clock tree with minimal sharing
- ✅ TCXO for main system clock (low jitter)
- ✅ Differential LVDS for AT86RF215 data clocks
- ✅ Proper termination on crystal oscillators

**Concerns**:
- ⚠️ No programmable clock generator
  - **Impact**: Fixed clock frequencies
  - **Recommendation**: Consider Si5351 or similar for flexibility
- ⚠️ External clock input (J5) has DNP resistor
  - **Impact**: Cannot easily change system clock without rework
  - **Recommendation**: Populate R8/R9 as 0Ω for external clock option

**Rating**: ✅ **Good** (adequate for current design, limited flexibility)

### 4. USB Interface

**PHY**: USB3343-CP (ULPI, USB 2.0 High-Speed)

**Strengths**:
- ✅ Proper ULPI implementation (LVCMOS33, 60 MHz)
- ✅ All pins properly assigned to BANK 7
- ✅ 26 MHz reference clock from FPGA (configurable)
- ✅ Reset control from FPGA
- ✅ ESD protection on DP/DM (ESD8472MUT5G)
- ✅ USB Type-C connector (modern standard)
- ✅ 5.1K CC resistors for device mode

**Concerns**:
- ⚠️ **No common-mode choke** on VBUS
  - **Impact**: Potential EMI issues, may not pass USB-IF compliance
  - **Recommendation**: Add ferrite bead or CM choke (e.g., WE-CNSW 744235)
- ⚠️ **No TVS diode** on VBUS
  - **Impact**: Limited overvoltage protection
  - **Recommendation**: Add SMAJ5.0A or similar TVS
- ⚠️ **Differential pair routing** - need to verify on PCB
  - **Requirement**: 90Ω differential impedance, length matched to ±5 mil
  - **Recommendation**: Verify with impedance calculator and PCB stackup

**USB Data Rates**:
- Theoretical: 480 Mbps
- Practical: ~40 MB/s (320 Mbps)
- AT86RF215: ~14 MB/s
- MAX2771: ~8 MB/s
- **Total**: ~22 MB/s (55% utilization) ✅ Good margin

**Rating**: ✅ **Good** (functional, but needs EMI improvements for compliance)

### 5. AT86RF215 RF Interface

**Component**: AT86RF215M (Microchip dual-band RF transceiver)

**Frequency Ranges**:
- RF09: 389-1088 MHz (Sub-GHz)
- RF24: 2400-2483.5 MHz (2.4 GHz ISM)

**Strengths**:
- ✅ Differential LVDS data interface for high-speed I/Q
- ✅ Separate SPI control interface
- ✅ Proper clock distribution (26 MHz TCXO)
- ✅ RF baluns for impedance matching (B1: 2.4GHz, B2: Sub-GHz)
- ✅ U.FL connectors for external antennas (J11, J12)
- ✅ SMA option for lab use (J11, J12 can be SMA or U.FL)
- ✅ Clock output available (J14) for synchronization

**Interface Details**:
- Control: SPI @ up to 8 MHz (BANK 2)
- Data: LVDS differential pairs (BANKS 1/2)
  - TX: TXCLK, TXD (FPGA → AT86)
  - RX: RXCLK, RXD09, RXD24 (AT86 → FPGA)
- Sample Rate: Up to 4 MSPS per channel
- Data Width: 14-bit I/Q per channel

**Concerns**:
- ⚠️ **Diff pairs cross banks** (BANK 1 ↔ BANK 2)
  - **Impact**: Potential VCCIO mismatch issues
  - **Current**: Both banks are 3.3V, so OK
  - **Recommendation**: Keep in mind for future bank voltage changes

- ⚠️ **LVDS termination not shown**
  - **Impact**: May cause reflections at high data rates
  - **Recommendation**: Verify 100Ω differential termination on PCB
  - **Location**: Terminate at FPGA end for RX, at AT86 end for TX

- ⚠️ **RF matching network**
  - **Need**: Verify impedance matching network values
  - **Components**: C28-C31, L1 (need to match to antenna impedance)
  - **Recommendation**: Use Microchip AN2906 for matching guidance

**Pin Conflict Resolution**:
- ✅ AT86_MOSI corrected to H14 (PR14D) - conflict resolved

**Rating**: ✅ **Good** (verify termination and PCB routing)

### 6. MAX2771 GNSS Frontend

**Component**: MAX2771ETI+ (Analog Devices multi-GNSS receiver)

**Supported Systems**:
- GPS L1 (1575.42 MHz)
- Galileo E1 (1575.42 MHz)
- GLONASS L1 (1602 MHz)
- BeiDou B1 (1561.098 MHz)

**Strengths**:
- ✅ 2-bit I/Q ADC output (simple FPGA interface)
- ✅ Integrated LNA and mixer
- ✅ Programmable via SPI (3-wire)
- ✅ 16.368 MHz reference clock (optimal for GPS)
- ✅ Lock detect output for PLL monitoring
- ✅ RF input via U.FL (J13)
- ✅ Good power supply filtering (FB beads, multiple caps)

**Interface Details**:
- Control: 3-wire SPI (SDATA, SCLK, CS_N) - BANK 3
- ADC: 2-bit sign-magnitude I/Q @ 16.368 MSPS
- Clock: ~16.368 MHz output to FPGA
- Data Rate: 16.368 MHz × 4 bits/sample = 65.5 Mbps → ~8.2 MB/s

**Concerns**:
- ⚠️ **No external LNA shown**
  - **Impact**: May need active antenna or external LNA for weak signals
  - **Recommendation**: Design for active antenna option (bias tee on J13)

- ⚠️ **RF matching network**
  - **Components**: C116-C126, L5-L8
  - **Need**: Verify values match datasheet recommendations
  - **Recommendation**: Use MAX2771 eval board as reference

- ⚠️ **ADC sample rate fixed**
  - **Impact**: Cannot adjust for different bandwidth requirements
  - **Current**: 16.368 MHz is good for GPS L1
  - **Recommendation**: Implement decimation in FPGA if lower rates needed

**Preset Configurations** (from peripherals/max2771.py):
- ✅ GPS L1: 2.046 MHz IF, 2.2 MHz BW
- ✅ Galileo E1: 2.046 MHz IF, 2.2 MHz BW
- ✅ GLONASS L1: 2.046 MHz IF, 4.2 MHz BW

**Rating**: ✅ **Good** (verify RF matching, consider active antenna support)

### 7. ESP32-S3 Integration

**Component**: ESP32-S3FH4R2 (Espressif WiFi/BT MCU)

**Functions**:
1. WiFi/Bluetooth connectivity
2. FPGA programming via JTAG
3. System control and configuration
4. USB-to-UART bridge

**Strengths**:
- ✅ Dual-core Xtensa LX7 @ 240 MHz
- ✅ 4MB Flash, 2MB PSRAM (FH4R2 variant)
- ✅ WiFi 802.11 b/g/n + Bluetooth 5.0
- ✅ Direct JTAG connection to FPGA (saves external programmer)
- ✅ Separate USB Type-C for ESP32 programming
- ✅ PCB antenna with matching network (L9, L10)
- ✅ GPIO connections to FPGA for control

**Interface to FPGA**:
- JTAG: TDO, TCK, TDI, TMS (BANK 8)
- GPIO: 4× general purpose (GPIO6-9 → PT4A, PT6A, PT18B, PT29A)
- PROGRAMN control: Can trigger FPGA reconfiguration

**Concerns**:
- ⚠️ **Shared JTAG**
  - **Impact**: Cannot use external JTAG while ESP32 is active
  - **Workaround**: ESP32 firmware must tri-state JTAG when not in use
  - **Recommendation**: Add tri-state control in ESP32 firmware

- ⚠️ **WiFi antenna design**
  - **Need**: Verify antenna matching and placement
  - **Recommendation**: Use Espressif PCB Design Guidelines
  - **Keepout**: Maintain antenna clearance area

- ⚠️ **Power consumption**
  - **WiFi active**: ~240mA @ 3.3V
  - **Impact**: Significant load on 3.3V rail
  - **Recommendation**: Consider separate LDO for ESP32 if noise is an issue

**Rating**: ✅ **Excellent** (powerful integration, good feature set)

### 8. SD Card Interface

**Component**: TF-01A (MicroSD slot)

**Strengths**:
- ✅ 4-bit SD mode for higher bandwidth
- ✅ Card detect pin for hot-plug support
- ✅ Pull-up resistors on CMD and DAT lines
- ✅ Proper BANK 1 assignment (LVCMOS33)

**Interface**:
- Mode: 4-bit SD (not SPI mode)
- Speed: Up to 25 MHz (SD default speed)
- Maximum: 50 MHz (SD high-speed mode)
- Bandwidth: Up to 25 MB/s @ 50 MHz

**Concerns**:
- ⚠️ **No level shifters**
  - **Current**: 3.3V LVCMOS on both sides - OK
  - **Future**: If switching to 1.8V signaling, need level shifters
  - **Recommendation**: Design firmware for 3.3V mode only

- ⚠️ **No series termination resistors**
  - **Impact**: Potential overshoot on clock line
  - **Recommendation**: Add 33Ω series resistors on CLK and CMD

**Use Cases**:
- Configuration file storage
- Data logging (GNSS tracks, RF captures)
- Firmware updates

**Rating**: ✅ **Good** (functional, consider termination improvements)

### 9. Configuration and JTAG

**Configuration Flash**: W25Q32JVSSIQ (32 Mbit Quad SPI)

**Strengths**:
- ✅ Adequate size for FPGA bitstream (~2 Mbit) + firmware (~1 Mbit)
- ✅ Quad SPI for fast configuration (~10 seconds)
- ✅ Master SPI mode (FPGA configures itself)
- ✅ Proper configuration pin strapping:
  - CFG[2:0] = 000 (Master SPI mode)
  - Pull-ups/pull-downs as per TN1260
- ✅ PROGRAMN, INITN, DONE indicators with LEDs

**JTAG**:
- ✅ Shared between ESP32 and J3 header
- ✅ Standard 10-pin connector option
- ✅ Pull-ups on TDI, TMS (per IEEE 1149.1)

**Concerns**:
- ⚠️ **Flash size**
  - **Current**: 32 Mbit = 4 MB
  - **Bitstream**: ~1.5 MB (LFE5U-25F)
  - **Margin**: ~2.5 MB for firmware/data
  - **Recommendation**: OK for current design, consider 64 Mbit for future

**Rating**: ✅ **Good**

### 10. PCB Design Considerations

**Layer Stack** (assumed 4-layer):
1. Top: Signal
2. GND plane
3. Power planes (3.3V, 1.1V, 2.5V)
4. Bottom: Signal

**Critical Routing**:

1. **USB Differential Pairs** (DP/DM):
   - Impedance: 90Ω ± 10% differential
   - Length match: ±5 mil
   - Keepout: 3× trace width

2. **ULPI Data Bus**:
   - Impedance: 50Ω single-ended
   - Length match: ±250 mil (meets ULPI spec)
   - Trace width: ~6 mil (for 50Ω on typical stackup)

3. **AT86RF215 LVDS Pairs**:
   - Impedance: 100Ω ± 10% differential
   - Length match: ±5 mil per pair
   - Crossing banks: Requires careful routing

4. **Clock Distribution**:
   - 26 MHz: Star topology from oscillator
   - USB 60 MHz: Short, direct trace to FPGA
   - MAX2771 16.368 MHz: Short, direct trace

**Recommendations**:
1. ✅ Use controlled impedance for high-speed signals
2. ✅ Guard traces around USB and LVDS pairs
3. ✅ Solid GND plane under FPGA
4. ✅ Thermal vias under power regulators
5. ⚠️ Verify actual impedances with PCB calculator
6. ⚠️ Consider 6-layer stackup for better signal integrity

**Rating**: ⏸️ **Pending** (requires PCB layout review)

## Design Improvements & Recommendations

### High Priority

1. **Add USB EMI Protection**
   - Common-mode choke on VBUS (e.g., WE-CNSW 744235)
   - TVS diode on VBUS (SMAJ5.0A or SRV05-4)
   - **Benefit**: Better EMI compliance, protection

2. **Add Bulk Capacitance on 1.1V Rail**
   - 47µF-100µF tantalum or polymer cap near U6 output
   - **Benefit**: Better transient response during FPGA switching

3. **Verify LVDS Termination**
   - 100Ω differential termination on all LVDS pairs
   - Locate at receiving end (FPGA for RX, AT86 for TX)
   - **Benefit**: Reduced reflections, better signal integrity

4. **Add SD Card Series Termination**
   - 33Ω series resistors on CLK and CMD
   - **Benefit**: Reduced overshoot, better signal quality

### Medium Priority

5. **Consider LFE5U-45F Option**
   - Populate DNP for 45F variant
   - **Benefit**: More headroom for future features
   - **Cost**: ~$10-15 more per unit

6. **Active Antenna Support for GNSS**
   - Bias tee circuit on J13
   - Jumper to enable/disable antenna power
   - **Benefit**: Better GNSS sensitivity with active antenna

7. **External Clock Input**
   - Populate R8/R9 as 0Ω (currently DNP)
   - **Benefit**: Flexibility for external reference clock

8. **Separate ESP32 Power**
   - Dedicated LDO for ESP32 (TLV1117-33 or similar)
   - **Benefit**: Reduced noise coupling to FPGA IO

### Low Priority

9. **Add Test Points**
   - Power rail test points
   - Critical signal test points (CLK, USB, LVDS)
   - **Benefit**: Easier debugging and validation

10. **Component Selection Alternatives**
    - Consider LFE5U-45F for production
    - Consider larger flash (W25Q64) for future expansion
    - **Benefit**: More margin for growth

## Conclusion

The Vahya MINI hardware design is a **well-executed SDR and GNSS platform** with good engineering practices. The integration of ESP32-S3 for WiFi/BT and FPGA programming is particularly clever, eliminating the need for external programmers.

**Key Strengths**:
- Clean, well-organized design
- Good component selection
- Unique feature combination (SDR + GNSS + WiFi)
- Adequate power delivery and decoupling
- Good clock distribution

**Areas for Improvement**:
- USB EMI protection
- LVDS termination verification
- FPGA resource headroom
- Some PCB routing challenges (cross-bank differential pairs)

**Overall Assessment**: ✅ **Production Ready** with recommended improvements

**Recommended Actions**:
1. Implement high-priority improvements (EMI protection, termination)
2. Validate PCB layout against signal integrity requirements
3. Perform comprehensive hardware testing
4. Consider LFE5U-45F for production if adding more features
